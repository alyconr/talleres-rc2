# T003 — Conclusión y recomendación

## Decisión recomendada

Para el MVP, preferir **Meta WhatsApp Cloud API directa detrás del puerto de WhatsApp del módulo de conversaciones**, condicionada a que el equipo complete el alta de Tech Provider / onboarding multicliente y asuma la operación de webhooks, credenciales, reintentos y soporte.

La razón económica es conservar únicamente las tarifas variables de Meta por mensajes billables y evitar el cargo de USD 0,005 por cada mensaje que Twilio publica, así como los cargos fijos mensuales de Partner Platform que 360dialog publica. La arquitectura local ya propone encapsular WhatsApp en un puerto del módulo de conversaciones, por lo que un adaptador directo no expone detalles del proveedor al resto del sistema.

## Cuándo elegir otra opción

- **Twilio:** elegirlo si reducir el tiempo inicial de integración y delegar la operación de la API compensa el cargo publicado de USD 0,005 por mensaje entrante o saliente. No asumir que elimina el trabajo de onboarding SaaS: Twilio exige a los ISV completar el programa Meta Tech Provider y la integración técnica. Confirmar en una prueba cómo mapear cada taller/WABA a cuenta o subcuenta y cómo migrar el número después.
- **360dialog:** elegirlo si onboarding administrado, soporte y operación multicanal son requisitos prioritarios que compensen su plan de partner. Pedir cotización escrita, en particular aclarar precio final por canal, canales incluidos, moneda/IVA y opciones de pago directo vs. pago por partner.

## Confianza y límites

Confianza **media-baja**. La elección cambia con tres datos que hoy no están fijados: talleres y mensajes mensuales, capacidad interna para operar la integración, y esfuerzo real del flujo Tech Provider de Meta. La tarifa oficial de Meta para Colombia no se pudo leer en forma dinámica durante la consulta; por eso no se incluyó un monto Meta por plantilla y no se utilizó una fuente secundaria para completarlo. La documentación comercial de 360dialog y Twilio no siempre presenta igual las reglas de facturación de Meta; ante discrepancias debe prevalecer la tarifa/política oficial vigente de Meta y confirmarse con el proveedor.

No se verificó el flujo real con una cuenta o número colombiano, no se obtuvo cotización comercial, y no se midió código ni esfuerzo de desarrollo. Esta recomendación no autoriza contratar un proveedor ni integrar la API.

## Próximos pasos si se aprueba implementación

1. Confirmar costo, moneda y flujo de facturación con Meta y cualquier BSP.
2. Validar Tech Provider/Embedded Signup con un taller piloto y un número colombiano no productivo.
3. Diseñar credenciales por taller, firma/autenticación y validación de webhooks, idempotencia, política de reintentos y redacción de logs antes de conectar números reales.
4. Mantener el proveedor detrás del puerto de conversaciones para que la decisión pueda revisarse sin cambiar contratos entre módulos.
